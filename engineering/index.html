How Perch compares

Perch is one of seven clients for a self-hosted Hermes Agent. Below: what it measures at, how it lines up against each of the others on every axis that matters for a phone, and where it is behind. Perch numbers are read off measurement artefacts; competitor cells are from each project's README as of 2026-09-10.

Against every other client

Seven clients exist. Two are native iOS, two native Android, one a PWA behind a proxy, one an official Expo shell that wraps the desktop renderer in a WebView, and Perch. hermes-android is the strongest Android alternative; Hermex has the most stars and needs a separate third-party server.

And the incumbent nobody lists: Telegram, through the gateway's own adapter. It wins on push — instant, everywhere, no setup — and loses on everything an approval needs: the exact command on screen, a fail-closed deadline shown as a countdown, a two-tap confirm, and a record of what was decided. Perch treats that bar as the one to clear.

Where Perch is behind

  • Attachments: hermes-android takes 10 files at 16 MiB each over the API everyone has; Perch takes one at 8 MiB and only with a dashboard paired, because the api_server surface offers none.
  • Read-aloud: hermes-android speaks replies. Perch has no text-to-speech.
  • App Store: Hermex is on it; goncharik is on TestFlight. Perch's iOS build runs on the simulator and ships in the release; a signed IPA waits on a developer membership.
  • Adoption: Hermex has 1.3k stars. Perch is in its first closed test.
  • Extra dashboard surfaces: Hy4ri shows live logs, processes, webhooks and a kanban; hermes-android has a memory viewer, projects and encrypted backup. Perch deliberately builds none of these.
  • OAuth to the dashboard: goncharik supports it. Perch does not.
  • Material You: Hy4ri picks up the wallpaper palette. Perch has three fixed schemes.

Not measured yet

Budgets exist for these; the numbers do not, and the page will not pretend otherwise. Battery per hour of streaming and frame drops during a stream need a physical device — an emulator renders through the host GPU and answers dishonestly. Crash-free sessions and ANR rate need real users, and the gates are set at 99.7 % and 0.2 % against Play's bad-behaviour lines of 98.91 % and 0.47 %. Memory at 10,000 messages is bounded by design — 1,000 rendered rows, 50 per page — and unmeasured.

What it will not do

  • Run a relay. Some clients route phone → their cloud → your agent and delete connection setup entirely. That is a real convenience bought with a server you do not run. Perch runs none, and owes you a legible tunnel instead.
  • Invent a message field. An attached file is never rendered back in the transcript, because no message the gateway returns carries one.
  • Install a private CA. Named in the connect flow rather than failing obscurely.
  • Push multi-device. Another device's changes arrive by a 30 s re-read, not an event.
